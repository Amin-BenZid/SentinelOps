v0.1 ALPHA
The Core
One agent. One command. Unified metrics, smart alert correlation, and a clean dashboard. The foundation everything else builds on — bulletproof before we go further.
Months 1 – 3
Goal: best lightweight
unified monitoring tool
Features
Universal Metric Collection MUST
Connects to Prometheus, Docker API, and a lightweight push agent for bare servers. No Prometheus? Drop a single binary. Works on any Linux/Windows host.
Layer 1 — Rules Engine MUST
YAML-defined threshold rules that fire instantly from day one. No training data required. cpu > 85% for 3min → alert. Simple, fast, reliable.
Alert Deduplication MUST
Groups duplicate alerts from the same root event. One cascading failure = one notification, not fifty. Fingerprinting + time-window bucketing.
Alert Correlation MUST
Links related alerts together — CPU spike + memory high + latency spike become one grouped event with a single severity score.
React Dashboard MUST
Live service health overview, active alert feed, metric sparklines, recent events. Clean, fast, mobile-responsive. Built with Recharts — no Grafana dependency.
Slack + Email Alerts MUST
Webhook-based Slack notifications and SMTP email alerts. Configurable per-rule severity routing. Quiet hours support to avoid 3AM noise for low-severity events.
Docker Compose Deploy MUST
Truly one command: `docker compose up -d`. Single SQLite database by default. No Redis. No TimescaleDB. No external dependencies in the default config.
Native CloudWatch Support NICE
Direct AWS CloudWatch API integration. No Prometheus exporter needed. Just AWS credentials in config and you're ingesting EC2, RDS, Lambda metrics immediately.
Log Ingestion (Basic) NICE
Tail local log files and parse error patterns. Regex-based rules on log content. Useful for teams with no metrics setup at all — logs are universal.
Webhook Ingest API NICE
HTTP POST endpoint for custom metric ingestion. Any system that can make an HTTP call can feed SentinelOps. Simple JSON schema, no auth friction in v0.1.

Why this scope

v0.1 does one thing: replace the pain of wiring Prometheus + Grafana + Alertmanager together. That's already a win developers will tweet about. Shipping this bulletproof is more valuable than shipping v0.5 half-broken.

SQLite as default keeps the Docker Compose truly simple — one compose file, two containers (agent + dashboard). No database administration. No connection strings. It just works.

The goal for v0.1 is the first GitHub star and the first "good first issue" contributor. Not feature completeness.

v0.2 BETA
Intelligence
The monitoring gets smarter. ML anomaly detection activates after 24h of data. Human-in-the-loop remediation replaces dangerous auto-actions. Incidents get their own lifecycle.
Months 4 – 6
Goal: ML that actually
helps, safely
New Features in v0.2
Layer 2 — Isolation Forest ML MUST
Trains on your infra's normal baseline after 24h of data. Detects statistical anomalies without fixed thresholds. CPU spikes that are normal for you won't fire. Runs in a separate lightweight process — never on the monitored host.
Human-in-the-Loop Remediation MUST
AI suggests an action. Human approves with one Slack button click. No autonomous changes to production. Eliminates the liability of auto-remediation while keeping the speed advantage.
Incident Management MUST
Auto-create incidents from anomalies. Open → In Progress → Resolved lifecycle. Timeline of all events during the incident. MTTR and MTTD tracking over time.
On-Call Rotation MUST
YAML-defined rotation schedule. Auto-assign incidents to the on-call engineer. Escalation after N minutes if unacknowledged. Email + Slack notification on assignment.
Kubernetes / Helm Chart MUST
Production-grade Helm chart for K8s deployment. Connects to kube-state-metrics and cAdvisor automatically. HPA-aware — doesn't alert on expected scaling events.
Plugin System MUST
BasePlugin interface in Python. Community can write and submit plugins via PR. Built-in plugins: restart_pod, restart_container, notify_slack, notify_email, run_script, webhook.
Azure Monitor + GCP Support NICE
Native Azure Monitor API and GCP Cloud Monitoring API connectors. Full multi-cloud support without requiring Prometheus exporters on any provider.
PostgreSQL Upgrade Path NICE
One config flag migrates from SQLite to PostgreSQL for teams with large metric volumes. TimescaleDB extension optional for serious time-series workloads.
Adaptive Thresholds NICE
Rules engine learns your normal patterns and adjusts thresholds dynamically. Friday traffic spikes stop generating false alerts. Seasonal patterns are respected automatically.

Months 7 – 9
Goal: the demo that

New Features in v0.3
Layer 3 — LLM Root Cause MUST
LLM explains anomalies in plain English with metric context pre-aggregated before sending. Works with Ollama (local, free, private), OpenAI, or Anthropic. OFF by default — opt-in only.
AI Chat Interface MUST
Natural language questions about your infra answered in real time. "Why is api-service slow?" "How bad was last week?" "Will I have issues Friday?" The AI reads from your DB — never touches prod.
Context Memory — Incidents MUST
AI remembers past incidents and references them. "This pattern matches Incident #31 from 3 weeks ago. Last time it was fixed by rolling back v2.3.1." Gets smarter the longer it runs.
Postmortem Auto-Draft MUST
When an incident is resolved, LLM drafts a postmortem with timeline, root cause, impact, and action items. Engineer reviews and edits — never published automatically.
Change Tracking MUST
Records every deploy, config change, and scaling event with a timestamp. AI correlates anomalies with recent changes automatically. "CPU spike started 2 minutes after your deploy."
Runbook Integration NICE
Point SentinelOps at a folder of markdown runbooks. LLM reads them and references relevant runbook steps during incidents. Your team's knowledge becomes instantly searchable.
Service Topology Map NICE
Auto-discovers which services call which from network metrics and traces. Used by LLM to trace cascading failures upstream. Visualized as an interactive graph in the dashboard.
Full Documentation Site MUST
Docusaurus-based docs site. Getting started in 5 minutes. Provider setup guides for AWS, GCP, Azure. Plugin authoring guide. Deployed to GitHub Pages automatically.

Full Platform
The complete vision lands. Cost intelligence, predictive forecasting, and opt-in auto-remediation with confidence thresholds. Public launch on Hacker News and Product Hunt.
Month 12
Goal: public launch,

New Features in v1.0
Cost Intelligence — Basic MUST
Idle resource detection (CPU avg <5% for 5 days), rightsizing suggestions, and cost anomaly alerts. Connects to AWS Cost Explorer, GCP Billing API, Azure Cost Management. No complex FinOps engine yet.
Predictive Forecasting MUST
Facebook Prophet-based time-series forecasting. Predicts disk full, traffic surges, memory exhaustion. 14-day forecast horizon. "Your disk will be full in ~6 days at current growth rate."
Auto-Remediation — Opt-In MUST
Full autonomous actions available — but only when: confidence score > 0.95, action is in an approved whitelist, and user has explicitly enabled it per-rule. Off by default forever.
LSTM Anomaly Detection NICE
Optional upgrade from Isolation Forest to LSTM for sequential pattern detection. Catches memory leaks, gradual degradation, and cyclical failure patterns. Runs on dedicated sidecar only.
Terraform Modules MUST
One-click Terraform deployment for AWS, GCP, and Azure. Provisions EC2/GCE/VM, networking, IAM roles, and installs SentinelOps automatically. True infrastructure-as-code onboarding.
Budget Forecasting MUST
Monthly cloud spend forecast with trend analysis. Alert when projected spend will exceed configured budget. Per-service cost breakdown visible in dashboard.
Full Context Memory NICE
Expands memory beyond incidents to include service topology, deploy history, config changes, and team runbooks. The longer SentinelOps runs, the better its explanations become.
Community Plugin Registry MUST
Public registry of community-submitted plugins. Install any plugin with: `sentinelops plugin install pagerduty`. Versioned, reviewed, and tested before publishing.

Chaos Engineering Integration MUST
Integrates with LitmusChaos and Chaos Mesh. Schedules controlled failure injections on staging. Verifies SentinelOps detects and responds correctly. Reports detection time and remediation success rate.
Full FinOps Engine MUST
Beyond idle detection — full cost allocation per service/team, reserved instance recommendations, spot instance opportunities, and multi-cloud cost comparison. Replaces Kubecost for K8s cost visibility.
Chaos Experiment Library NICE
Pre-built chaos experiments: CPU stress, memory hog, pod kill, network delay, disk fill, node drain. Each verifies a specific SentinelOps detection + remediation path end-to-end.
Multi-Tenant Support NICE
Single SentinelOps instance serving multiple teams or customers with full data isolation. RBAC with team-scoped dashboards, alerts, and incidents. Useful for MSPs and platform teams.
SLA / SLO Tracking NICE
Define SLOs (99.9% uptime, <200ms p99 latency). SentinelOps tracks error budgets in real time and alerts when burn rate will exhaust the budget before the window closes.
Advanced LLM Agents OPTIONAL
Multi-step reasoning agents that can investigate an incident across multiple services, correlate logs + metrics + traces, and produce a comprehensive root cause report autonomously.
Distributed Tracing OPTIONAL
OpenTelemetry integration for distributed tracing. Correlates traces with metric anomalies to pinpoint the exact service and line of code causing the slowdown.
Mobile App OPTIONAL
React Native app for incident acknowledgement, on-call management, and AI chat on mobile. Push notifications for critical alerts. One-tap approve/dismiss remediation suggestions.

Why chaos engineering is v2.0, not earlier

Chaos engineering only makes sense when your detection and alerting are already solid. Running chaos experiments before v0.3 is ready would just generate noise — you wouldn't trust whether SentinelOps caught the failure or missed it.

By v2.0, you have 12+ months of real incidents, tuned ML models, and proven remediation flows. That's when chaos experiments become a meaningful confidence check, not just a demo feature.

The same logic applies to full FinOps — teams don't trust cost recommendations from a tool they've been using for a week. After a year of accurate anomaly detection, they trust the cost suggestions too.
